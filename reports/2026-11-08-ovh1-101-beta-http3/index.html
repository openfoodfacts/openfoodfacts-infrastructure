    2026-10-30 OVH1 101 (proxy) enable HTTP/3 for beta.openfoodfacts.net#

    In order to enabling HTTP/3 for the first canary, it was was enabled for the OFF Explorer staging deployment. Following a guide from PB was followed. In the 101 LXC container, the QUIC key was generated and excluded from etckeeper.

    $ mkdir -p /etc/nginx/ssl/
$ openssl rand -base64 32 > /etc/nginx/ssl/quic_host.key
$ chmod 400 /etc/nginx/ssl/quic_host.key
$ chown www-data:www-data /etc/nginx/ssl/quic_host.key
$ echo "nginx/ssl/quic_host.key" >> /etc/.gitignore
$ git add /etc/.gitignore
$ git commit -m "chore: Ignore QUIC key from git"

    Created a new reusable HTTP/3 config at /opt/openfoodfacts-infrastructure/confs/ovh1-reverse-proxy/nginx/conf.d/http3.conf, and created a new symlink

    http3_stream_buffer_size 1m;
quic_retry on;
ssl_early_data off;
quic_gso off;

quic_host_key /etc/nginx/ssl/quic_host.key;

    $ ln -s  /opt/openfoodfacts-infrastructure/confs/ovh1-reverse-proxy/nginx/conf.d/http3.conf /etc/nginx/conf.d/http3.conf

    and updated the nginx/sites-enabled/beta.openfoodfacts.net.conf to enable HTTP/3:

    diff --git a/confs/ovh1-reverse-proxy/nginx/sites-enabled/beta.openfoodfacts.net.conf b/confs/ovh1-reverse-proxy/nginx/sites-enabled/beta.openfoodfacts.net.conf
index 8f1054a16..32ab3a7fd 100644
--- a/confs/ovh1-reverse-proxy/nginx/sites-enabled/beta.openfoodfacts.net.conf
+++ b/confs/ovh1-reverse-proxy/nginx/sites-enabled/beta.openfoodfacts.net.conf
@@ -6,6 +6,7 @@ map $uri $beta_off_net_basic_auth_setting {

 server {
     listen 443 ssl; # managed by Certbot

+    listen 443 quic reuseport;
     ssl_certificate /etc/letsencrypt/live/beta.openfoodfacts.net/fullchain.pem; # managed by Certbot
     ssl_certificate_key /etc/letsencrypt/live/beta.openfoodfacts.net/privkey.pem; # managed by Certbot
     include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
@@ -14,6 +15,9 @@ server {
     server_name  beta.openfoodfacts.net;

     http2 on;

+    http3 on;
+
+    add_header Alt-Svc 'h3=":443"; ma=3600, h3-29=":443"; ma=3600' always;

     # off:off basic username to avoid indexation by bots (it's staging env)
     auth_basic_user_file /etc/nginx/off.htpasswd;

    Allowed UDP 443 in the firewall:

    $ iptables -A INPUT -p udp -m udp --dport 443 -j ACCEPT
$ ip6tables -A INPUT -p udp -m udp --dport 443 -j ACCEPT

    From another host, the connection was tested successfully using docker run -it --rm ymuski/curl-http3 curl -ILv https://beta.openfoodfacts.net/health --http3-only, http3check, and http3-test.

    I tested without the Alt-Svc header first, as asked for in https://github.com/openfoodfacts/openfoodfacts-infrastructure/issues/679#issue-5292086065. For each nginx config change, I first ran nginx -t and upon success systemctl reload nginx.service.

    The UDP firewall rules were manually added to /etc/iptables/rules.v4 and /etc/iptables/rules.v6, as no other management tool seems to be in place.
